# Ocean Personal Website PRD

> Status: Draft v0.3  
> Updated: 2026-07-28  
> Product concept: Tidal Archive / 潮汐档案（暂定）

## 1. 产品概述

这是一个面向招聘者的沉浸式个人网站，用写实海洋、时间变化和摄影叙事展现 Ocean 在 AI 应用、Vibe Coding、创意开发和视觉艺术方面的能力。

网站既承担个人介绍和求职展示功能，也是一个可以持续发布项目、摄影、文章、生活记录与创意实验的个人数字档案馆。

## 2. 产品目标

### 2.1 核心目标

- 让招聘者在 10 秒内理解站点主人的身份与方向。
- 让招聘者在 30 秒内找到精选项目、核心能力与简历入口。
- 通过网站本身证明 AI 应用开发、Vibe Coding、交互实现和视觉表达能力。
- 建立可以长期更新的作品、摄影和个人内容管理系统。

### 2.2 非目标

- 第一版不制作完整社交社区。
- 第一版不开放访客注册和评论。
- 第一版不追求游戏级真实海洋模拟。
- 第一版不开放原始摄影文件下载。

## 3. 目标用户

### 3.1 核心用户

- AI 应用方向的招聘者与面试官。
- 寻找创意技术、AI 产品或全栈开发人才的团队负责人。

### 3.2 次要用户

- 同行开发者。
- 摄影爱好者。
- 潜在合作伙伴。

## 4. 个人定位

- 差异化定位：AI / Vibe Coding 与视觉艺术结合的实践者。
- 英文名：Ocean。

暂定英文表达：

暂定中文表达：

## 5. 品牌与视觉概念

### 5.1 暂定品牌

- 主名称：Ocean。
- 概念名称：Tidal Archive / 潮汐档案。
- 品牌水印采用图形 Logo，正式 Logo 待设计；视觉 Demo 使用临时波浪符号。
- 域名：尚未购买。

### 5.2 核心视觉

- 写实海面。
- 整体视觉采用珍珠白、泡沫白、浅海蓝和少量珊瑚橙，保持明亮通透。
- 内容采用 Editions 式章节叙事、档案编号和大字号编辑排版，但不直接复刻参考网站。
- 日出、白天、黄昏、夜晚四种状态。
- 默认状态根据访客本地时间自动选择。
- 访客可以手动切换海洋状态。
- 海洋场景用于建立氛围，不能阻碍招聘者获取信息。

### 5.4 创新导航

- 取消传统顶部导航栏。
- 使用固定在左下角的“潮汐罗盘”作为全站入口。
- 点击罗盘后展开全屏海图，通过海域坐标进入独立页面。
- Surface 对应首页，Current 对应作品，Reef 对应摄影，Shore 对应关于，Deep 对应日志。
- 每个栏目使用独立路由，并在视觉上保持同一海洋世界观。

### 5.3 声音

- 默认静音。
- 用户主动开启海浪或环境声音。
- 记住用户的声音偏好。
- 移动端默认关闭。

### 6.1 首页

- 写实海洋首屏。
- 姓名与艺术化定位文案。
- 精选作品入口。
- 简历入口。
- 精选三个 AI / Vibe Coding 项目。
- 能力概览。
- 精选摄影入口。
- 简短经历与联系区域。

### 6.2 Work

- 第一版预计展示约三个项目。
- 项目方向以 Agent 工作流、AI 效率工具和 Vibe Coding 为主。
- 每个项目包含问题、方案、AI 能力、职责、技术栈、过程、结果和复盘。

### 6.3 Photography

- 当前约 500 张照片。
- 当前照片主要格式为 JPEG，目录路径待提供。
- 分类：Ocean & Nature、City、Travel、Portrait、Black & White、Daily Fragments。
- 支持年份和地点辅助筛选。
- 不允许下载原图。
- 公开展示图必须带水印。

### 6.4 About 与 Resume

- 个人介绍。
- 教育经历。
- 实践与项目经历。
- 技能与工具。
- 中英文核心内容
- 简历文件下载。

### 6.5 Journal 与 Lab

- Journal 用于技术文章、Vibe Coding 记录、爱好与生活内容。
- Lab 用于交互实验、AI 小工具、Shader 和创意编码作品。
- 以上内容可以在第二阶段完善。

## 7. 国际化

- 网站以中文为主。
- 首页、About、Resume、项目摘要和 Contact 提供英文。
- 第一版不要求所有长文章逐字双语。
- 内容后台允许分别填写中文字段和英文字段。

## 8. 管理后台

后台路径：`/studio`。

### 8.1 登录与权限

- 支持 GitHub OAuth。
- 支持管理员邮箱登录作为备用方式。
- 只有配置的 GitHub 账号或邮箱能够进入。
- 使用 Supabase Row Level Security 保护写入操作。

### 8.2 第一阶段功能

- Dashboard。
- 项目新增、编辑、排序、草稿和发布。
- 摄影集新增、编辑、排序、草稿和发布。
- 照片批量上传、批量标记与失败重试。
- 首页文案和精选内容配置。
- 简历与联系方式配置。
- 海洋默认视觉参数配置。

### 8.3 使用设备

- 优先适配桌面管理。
- 移动端只保证基本查看，不要求完整编辑体验。

## 9. 摄影媒体管线

### 9.1 存储版本

- 原图：Supabase 私有存储，不向访客暴露。
- 展示图：限制分辨率、压缩并合成水印。
- 缩略图：用于首页和摄影集列表。

### 9.2 上传流程

1. 管理员批量选择照片。
2. 浏览器直接上传至私有存储。
3. 创建图片处理任务。
4. 异步生成展示图和缩略图。
5. 管理员补充分类、地点、时间和说明。
6. 保存草稿并预览。
7. 批量发布。

### 9.3 保护限制

- 原图地址不发送到浏览器。
- 展示版本嵌入永久水印。
- 前端禁用普通拖拽和右键保存，仅作为辅助措施。
- 无法阻止截图，产品文案不得承诺绝对防下载。

### 10.2 后端与数据

- Supabase PostgreSQL。
- Supabase Auth。
- Supabase Storage。
- Drizzle ORM。
- TipTap 内容编辑器。
- 异步媒体任务队列方案待技术验证。

### 10.3 部署

- Vercel。
- Supabase 托管数据库和存储。
- 自定义域名待购买。
- 云服务预算目标：每月不超过人民币 50 元。

## 11. 性能与可访问性

- 3D 场景延迟加载，优先显示姓名和核心行动按钮。
- 高性能设备使用完整 WebGL 海面。
- 普通设备降低几何复杂度、像素比和后处理效果。
- 移动端使用简化海面或预渲染视觉。
- WebGL 不可用时展示静态海面图。
- 支持 `prefers-reduced-motion`。
- 摄影图片使用响应式尺寸、懒加载和模糊占位。
- 目标：核心招聘信息不依赖 JavaScript 和 3D 场景才能阅读。

## 14. 成功标准

- 招聘者在首屏可以看到身份、方向、项目入口和简历入口。
- 三个项目均有完整案例说明。
- 500 张摄影作品可以通过摄影集和筛选高效浏览。
- 管理员不修改代码即可新增和发布核心内容。
- 原始摄影文件不会通过公共页面暴露。
- 手机端可以顺畅浏览，桌面端提供完整沉浸体验。
